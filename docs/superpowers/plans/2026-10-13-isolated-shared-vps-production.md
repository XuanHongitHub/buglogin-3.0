# Isolated Shared-VPS Production Plan

Status (2026-10-17): BugLogin-only PostgreSQL, TLS Redis, API, web, and Cloudflare Tunnel services are running on the BugIdea VPS under separate users, paths, ports, and resource limits. `api3.buglogin.com/v1/readyz`, `app3.buglogin.com/login`, and the production-facing `app.buglogin.com/login` return 200; the `app.buglogin.com` route is on the BugLogin-only tunnel. `api.buglogin.com` remains on 1.0. This is a reachable 3.0 production candidate, not a completed production release: current-worktree API contract parity, owner login, authenticated CRUD/sync, backups/monitoring, and native release gates remain open. The 3.0 database already contains the one-pass 1.0 control-plane clone (59 accounts, four platform admins); imported account email/password login is the current owner entry path. The owner accepts launching without 1.0 data, so that clone is no longer a release requirement; it remains preserved until a clean-start path is selected. Outbound recovery delivery is unsupported and not a startup prerequisite. Shared S3 credentials are an accepted temporary constraint under the application namespace `buglogin3/prod`, not an S3 ACL boundary. BugIdea Nginx, firewall, application, PostgreSQL, and Redis configurations were not changed.

Operational correction (2026-10-13): a `buglogin3-redis.service` unit was also present on the legacy BugLogin 1.0 VPS. It was disabled there without deleting its config/data; the 1.0 API health endpoint remained healthy. The BugIdea VPS remains the only active 3.0 Redis host.
