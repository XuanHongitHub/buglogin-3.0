# Wayfern Mobile Profile Implementation Plan

Status: partial implementation in the worktree; unverified. The API contract carries a typed target, but profile creation rejects Android/iOS before persistence and rejects explicit OS versions until the installed provider supports selection. Desktop launch contains a local CDP generation/apply/read-back path for supported targets. Mobile fingerprinting is not usable: upstream cross-OS generation requires a Wayfern token, BugLogin has no independent provider or authoritative OS/version catalogue, and the create/edit UI is not wired.
Spec: `docs/superpowers/specs/2026-10-15-wayfern-mobile-profile-design.md`.

Upstream boundary checked against [Donut's current REST API reference](https://donutbrowser.com/docs/rest-api/) and [Wayfern CDP helper reference](https://donutbrowser.com/docs/wayfern/): the OS selector includes Android/iOS, but a fingerprint OS different from the host requires Wayfern Pro/cross-OS entitlement; the helper documents the OS selector without a version selector. BugLogin must not treat the enum as proof that local generation is available. To meet the no-paid-plan product requirement, a BugLogin-owned provider and supported-version catalogue are still required; no external account/entitlement bypass is acceptable.

- [x] Add a typed profile fingerprint target DTO to the Rust domain and canonical command/OpenAPI contracts; validate the OS enum, Wayfern-only use, and numeric version form. The API stores the target in versioned profile runtime configuration, so profile-create idempotency includes it. Dynamic provider support checks remain in the desktop packet below.
- [x] Reject explicit operating-system versions in both typed and legacy profile-create paths until the installed Wayfern provider exposes a version selector. The pinned Donut refresh call sends only `operatingSystem`; accepting a version and failing only during desktop launch would leave an unusable persisted profile. The new `fingerprint_version_unsupported` response is source-only and unverified.
- [x] Parse legacy `runtimeConfig.wayfern` with the same schema version, required fingerprint target, and unknown-field rejection as desktop launch before accepting it. Malformed or differently-cased unsupported targets now fail at API/MCP/import boundaries instead of persisting and failing on the next launch. Source-only and unverified.
- [x] Move the versioned Wayfern runtime-config DTO and schema-version constant into the Rust domain crate; API validation/profile creation and desktop launch parsing now consume one shared contract. Source-only and unverified.
- [x] Move provider/version/runtime compatibility validation into the domain and call it from API create/legacy paths plus local migration activation. A local restore or non-Wayfern runtime can no longer bypass the same unsupported mobile/version checks applied by REST, MCP, and hosted import. Source-only and unverified.
- [x] Run the same domain target validator while resolving desktop launch configuration, so an older persisted mobile/version target fails before the browser process is started instead of failing after CDP launch. Source-only and unverified.
- [x] Centralize typed error code/title/status mapping with the domain validation error, so API and desktop surface the same canonical error contract. Source-only and unverified.
- [x] Persist the typed target in profile runtime configuration on create; profile records return that configuration, while generated fingerprint internals remain in the encrypted profile directory. Metadata updates preserve the configuration. Migration still needs explicit target mapping where legacy data represents one.
- [ ] Add an independent Rust fingerprint provider and an authoritative supported OS/version catalogue. Upstream `Wayfern.refreshFingerprint` accepts `wayfernToken` for cross-OS generation; BugLogin currently has no such token/provider. Do not claim iOS/macOS cross-OS support or expose options as available until this is resolved.
- [ ] Version selection has an additional upstream contract gap: the pinned Donut call sends only `operatingSystem`, while the current Wayfern docs list OS/timezone/language/location for `refreshFingerprint` and do not document an OS-version selector or catalogue. Do not persist or advertise iOS 15–26 choices until the installed provider exposes and confirms that capability.
- [x] Wire create/import/edit UI to the capability this build actually has: only the device's current operating system is selectable; an existing different target is visible as unavailable and must be changed before saving. The BugLogin form no longer exposes manual/per-launch fingerprint controls or an unregistered sample-generation command. Fingerprint editing in this supported local-OS flow is not paywalled. Legacy create/update adapters check the host OS before mutation, and edit persists the typed target through revision-bound canonical `profile.update` with API ACL and revision validation, resolving the profile's bound workspace rather than assuming the default workspace. Android/iOS and cross-OS runtime support remain unavailable; this is source-only and unverified.
- [x] Generated fingerprint is written under the profile directory, and the encrypted snapshot recursively includes ordinary files while rejecting symlinks; this covers `BugLogin/fingerprint.json` in the encrypted projection by source inspection. Cross-device runtime/restart behavior remains unverified.
- [ ] Add Donut-based UI controls driven by the provider catalogue, with typed unsupported/offline/error states; no catalogue exists yet.
- [ ] After all implementation is complete, run the consolidated API, desktop, contract, sync, Windows/macOS runtime, and UI interaction verification requested by the user.
