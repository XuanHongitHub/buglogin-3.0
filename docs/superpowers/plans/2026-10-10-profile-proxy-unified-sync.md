# Profile and Proxy Unified Sync Plan

Status: Rust API, canonical proxy revision dependencies, desktop API transport, client-side profile-file encryption/decryption, and a profile-scoped recovery drawer are implemented locally. New manifests reference canonical workspace proxy records by ID/revision instead of duplicating safe proxy metadata in every profile object set; legacy manifests with metadata objects remain readable and are still verified. The desktop persists each profile/resource key and its recovery key in the OS vault, adds a resource-scoped encrypted key envelope to each synced manifest, validates recovery through authenticated Tauri commands, and keeps envelopes out of browser profile projection. Proxy credential envelopes bind workspace, profile resource, proxy ID, and revision; the desktop proxy editor routes credentials through a revision-scoped OS-vault boundary, API mutations receive only the credential-present marker, and managed launch/snapshot require a matching proxy revision. An opaque API credential version now distinguishes credential replacement from metadata edits; one Rust service helper supplies the same version semantics to REST and MCP, and new commits validate it against canonical proxy state. Legacy manifests remain readable. This change is implemented locally and has not yet been verified. Credentials opened from a valid synced envelope are cached in the OS vault under that exact proxy revision, and vault failures release the acquired profile lease. V3 large-file chunk support spans manifest validation, canonical root binding, desktop encryption/cache/hydration, and OpenAPI. Snapshot reads one source file at a time, hashes files above the 64 MiB object threshold incrementally in 4 MiB reads, and stages ciphertext on disk. Hydration downloads/decrypts one object at a time, writes chunked logical files incrementally into an invisible generation staging directory, verifies files by streaming, and publishes by atomic directory rename after all checks pass. A process-level root lock prevents concurrent app instances from sharing this cache; startup removes abandoned, unpublished profile staging after a crash. Upload/download concurrency is capped at two. Interrupted-download retry is covered locally; interrupted upload, ambiguous commit, process death during a real API transfer, hosted staging, secure sharing-key distribution, durable recovery audit, and Windows/macOS release evidence remain open.

Source-only follow-up (2026-10-16): key rotation recipient device/session resolution is now shared by recipient listing, exact envelope activation, mutation-bound checks, and encrypted manifest compatibility. This keeps direct/group ACL resolution and active-device key coverage aligned and applies the same recipient/device caps at manifest validation. Tests/build and hosted persistence remain deferred.

Source-only follow-up (2026-10-17): REST and MCP proxy deletion now share one Rust guard that checks both direct profile bindings and queued profile-proxy assignments while the control mutation lock is held. This closes the MCP parity path that could delete a proxy still referenced by a queued assignment. Tests/build remain deferred.

Source-only follow-up (2026-10-17): proxy updates now use the same pending-assignment guard as deletion. The guard runs both before and inside the serialized mutation, preventing proxy metadata or credentials from changing after selection but before the profile's matching manifest activates that selection. A regression source covers the pending-assignment case; tests/build remain deferred.

Source-only follow-up (2026-10-17): proxy batch import now zeroizes partial or empty credential fields before returning a per-row failure. Previously, taking credentials out of the zeroizing parser row could drop an incomplete username/password as ordinary strings. Successful credentials still transfer into the zeroizing credential input. Tests/build remain deferred.

Source-only follow-up (2026-10-17): profile proxy assignment now uses one lifecycle rule at staging and manifest activation: only `created`, `ready`, and `failed` profiles may change proxy. `launching`, `running`, `stopping`, and `recovering` are rejected to prevent a transition racing the browser or sync operation. Regression source added for all transitional states; tests/build remain deferred.

Source follow-up (2026-10-19): metadata edits no longer fail solely because a staged proxy assignment exists. The assignment remains bound to its original profile revision; after a metadata revision change, sync activation rejects it as stale and the owner can GET then restage against the new revision. HTTP regression coverage was added alongside correcting stale actor-ID and proxy-create test fixtures. `cargo test -p buglogin-api --lib -- --test-threads=1` passes 208/208; the affected `http_profiles` / `http_leases` integration pair still needs a clean rerun after source edits. The live API process currently holds the target API executable on Windows, so the verification rerun has not yet completed.

## Stop conditions

- No verified BugLogin staging contract/credentials: stop before API writes or endpoint wiring.
- No secret-envelope/key lifecycle: stop proxy credential synchronization.
- No atomic manifest support: do not remove the current proxy toggle or claim unified production sync.
- Any data-loss, cross-workspace reference, credential leakage, or failed rollback evidence blocks release.
